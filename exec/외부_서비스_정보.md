### 가입·설정 절차

1. 카카오 계정으로 https://developers.kakao.com 로그인 → **내 애플리케이션 → 애플리케이션 추가하기**.
2. **앱 키** 탭에서 `REST API 키` 를 복사 → `KAKAO_OAUTH_CLIENT_ID`.
3. **카카오 로그인 → 보안** 에서 **Client Secret 을 생성하고 「사용함」으로 활성화** → `KAKAO_OAUTH_CLIENT_SECRET`.
   - ⚠️ 생성만 하고 활성화하지 않으면 `client_secret_post` 로 보낸 값이 무시되거나 거부된다.
4. **카카오 로그인** 을 활성화(ON)하고 **Redirect URI** 를 등록한다.

   | 환경 | Redirect URI |
   |---|---|
   | 운영 | `https://i15d106.p.ssafy.io/login/oauth2/code/kakao` |
   | 로컬 | `http://localhost:8080/login/oauth2/code/kakao` |

5. **동의항목** 에서 `프로필 정보(닉네임)` 만 필수/선택으로 설정한다. 이메일 등은 요청하지 않는다 — 비즈 앱 전환이 필요 없다.
6. **플랫폼 → Web** 에 사이트 도메인을 등록한다: `https://i15d106.p.ssafy.io`, `https://d106manda.vercel.app`, `http://localhost:5173`.

### 사용하는 엔드포인트 (`application.yml` 에 명시)

| 용도 | URI |
|---|---|
| 인가 | `https://kauth.kakao.com/oauth/authorize` |
| 토큰 | `https://kauth.kakao.com/oauth/token` |
| 사용자 정보 | `https://kapi.kakao.com/v2/user/me` |
| `user-name-attribute` | `id` |

### ⚠️ 주의

- Redirect URI 는 `{baseUrl}/login/oauth2/code/{registrationId}` 로 **요청 시점의 scheme/host 를 그대로 써서** 조립된다. 그래서 nginx 가 `X-Forwarded-Proto` / `X-Forwarded-Host` / `X-Forwarded-Port` 를 넘겨야 하고, Spring 쪽에 `server.forward-headers-strategy: framework` 가 있어야 한다(`application-prod.yml`). 빠지면 `http://backend:8080/...` 으로 계산되어 콘솔 등록값과 불일치한다.
- 키를 비워 두면(`disabled` 기본값) 앱은 정상 기동하고 **카카오 로그인만** 실패한다.
- 로그인 성공 후 리다이렉트 대상은 `FRONTEND_BASE_URL`(운영 `https://d106manda.vercel.app`)이다. 카카오 콘솔이 아니라 우리 `.env` 에 있다.

- **게이트웨이가 공식 엔드포인트보다 느리다.** 기본 타임아웃(15/20초)으로 두면 정상 응답이 잘려서, `BOT_STEP_TIMEOUT_SECONDS=25` / `BOT_TIMEOUT_SECONDS=45` 로 올려 두었다.
- **penalty 파라미터를 지원하지 않는다.** `BOT_FREQUENCY_PENALTY` / `BOT_PRESENCE_PENALTY` 를 0 이 아닌 값으로 주면 `Penalty is not enabled for models` 400 이 나면서 **모든 요청이 실패**한다. 기본값 0 은 "요청에 아예 넣지 않는다"는 뜻이다.
- 키를 비워 두면 앱은 정상 기동하고 **리포트 API 와 AI 코치 응답만** 실패한다.
- 비용 관리: 3단계가 토큰의 약 70% 를 쓰므로 거기만 `flash-lite` 로 내려 두었다(실측 2026-08-06: decide 5,000 vs classify 2,080 토큰). 모델 배치를 바꿀 때는 감이 아니라 골든셋으로 재는 절차가 `ai_livekit/.env.example` 에 적혀 있다.

### 가입·발급 절차

1. https://console.deepgram.com 에서 이메일로 가입(카드 없음).
2. **API Keys → Create a New API Key** → 값 복사.
3. AI EC2 의 `/opt/mandarin/ai_livekit/.env` 의 `DEEPGRAM_API_KEY` 에 넣고 `docker compose restart worker`.

### 왜 Deepgram 인가 (선택 근거)

1. **스트리밍**이라 자체 endpointing 을 한다 — 별도 VAD 패키지(silero)가 필요 없다. 배치 STT(Whisper)였다면 필요했다.
2. 무료 크레딧이 넉넉하고 카드가 필요 없다.
3. 한국어 지원(`language=ko`).

> 초기에 "Gemini 키가 이미 있으니 `livekit-plugins-google` 이 싸다"고 판단한 적이 있는데 **틀렸다.** Google Cloud STT 는 Gemini API 키가 아니라 **GCP 서비스 계정**이 필요하고, Gemini 기반 STT 플러그인은 존재하지 않는다. 이 판단으로 되돌리지 말 것.

### ⚠️ 주의

- 키를 비워 두면 **음성 입력만 비활성**되고 텍스트 대화는 그대로 동작한다(입장 시 채팅으로 알린다).
- `language="multi"` 에는 한국어가 없다. 한·영 혼용이 필요해도 `ko` 를 쓴다.
- 과금은 **보낸 오디오 길이** 기준이다. 그래서 `agent/listen.py` 의 RMS 무음 게이트(`SpeechGate`)가 말하지 않는 동안 프레임을 보내지 않고, 무음이 길어지면 스트림을 닫는다. `STT_SILENCE_DBFS`·`STT_HANGOVER_MS` 등을 낮추거나 올리면 인식률과 과금이 함께 움직인다.
- **TTS 는 쓰지 않는다.** 응답은 텍스트로만 나가므로 음성 합성 과금(세 번째 미터)이 없다.

- 버전을 `latest` 로 두지 않는다. 재배포 때 서버만 조용히 올라가면 문제 원인이 우리 변경인지 알 수 없게 된다.

- 열어야 하는 포트는 `포팅_매뉴얼.md` §2.4 표에 있다.

## 8. SSAFY GitLab — 저장소 + CI

| 항목 | 값 |
|---|---|
| 저장소 | `https://lab.ssafy.com/s15-webmobile1-sub1/S15P11D106` |
| CI 정의 | `.gitlab-ci.yml` (프론트 → Vercel, `ai_livekit` → AI EC2) |
| CI 변수 | `VERCEL_TOKEN` (Settings → CI/CD → Variables) |
| 러너 ① | SSAFY 공용 docker executor (`image: node:22`) — 프론트 잡 |
| 러너 ② | **AI EC2 에 직접 등록한 shell executor** (tag `ai-sfu`) — AI 잡 |

### 러너 ② 등록 절차 (AI EC2)

```bash
# gitlab-runner 설치 후
sudo gitlab-runner register \
  --url https://lab.ssafy.com/ \
  --token <프로젝트 러너 토큰> \
  --executor shell \
  --tag-list ai-sfu \
  --description "mandarin-ai-sfu"
sudo usermod -aG docker gitlab-runner   # docker compose 를 쓰므로 필요
sudo systemctl restart gitlab-runner
```

> **shell executor 를 쓴 이유:** 러너가 GitLab 으로 **아웃바운드만** 하므로 SSH 키를 CI 변수에 넣을 필요도, AI EC2 보안 그룹에 22번을 열 필요도 없다.
> ⚠️ 이 잡은 `before_script: []` 로 비워야 한다 — `default.before_script` 가 `npm install --global vercel` 인데 shell executor 호스트에 node 가 없다(같은 이유로 `default.image` 도 적용되지 않는다).

## 10. 키 교체(rotate) 시 체크리스트

값을 바꿀 때 같이 고쳐야 하는 자리를 놓치면 "기동은 되는데 특정 기능만 조용히 죽는" 상태가 된다.

| 바꾸는 값 | 같이 고칠 곳 |
|---|---|
| `LIVEKIT_API_KEY` / `SECRET` | ① 메인 EC2 `infra/.env` → `docker compose up -d backend` ② AI EC2 `.env` → `docker compose up -d` ③ 개발자 로컬 `ai_livekit/.env` |
| `POSTGRES_PASSWORD` | `infra/.env` + **기존 DB 볼륨의 실제 비밀번호**(볼륨을 지우지 않으면 초기값이 유지된다. `ALTER USER` 로 바꿔야 한다) |
| `JWT_SECRET` | `infra/.env` 만. 단 **기존 액세스/리프레시 토큰이 전부 무효**가 되어 전 사용자가 로그아웃된다 |
| 카카오 Client Secret | 카카오 콘솔에서 재발급 → `infra/.env` → 백엔드 재기동 |
| `GEMINI_API_KEY` | `infra/.env` 의 `GEMINI_API_KEY` **와** AI 쪽 `BOT_API_KEY` (같은 키다) |
| `DEEPGRAM_API_KEY` | AI EC2 `.env` → `docker compose restart worker` |
| `VERCEL_TOKEN` | GitLab CI/CD Variables |
| 프론트 배포 주소 | `FRONTEND_BASE_URL`, `CORS_ALLOWED_ORIGINS`, 카카오 콘솔 사이트 도메인 |
| AI EC2 의 IP | `livekit.yaml` 의 `node_ip`, `infra/nginx/conf.d/app.conf` 의 `proxy_pass` |

> ⚠️ **이 문서에는 실제 시크릿이 그대로 적혀 있다.** 저장소를 볼 수 있는 사람 전원이 읽을 수 있으므로, 평가·시연이 끝나면 위 표를 따라 키를 교체하고 `TEST_LOGIN_ENABLED`·`DEMO_ENABLED` 를 `false` 로 내리는 것을 권한다.
