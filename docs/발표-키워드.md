## 3. 백엔드 · 인증

| 키워드 | 정의 | 우리 것 |
|---|---|---|
| ★ **의존성 주입(DI)** | 객체가 의존성을 밖에서 받음 | 테스트에서 다른 설정 주입 가능 |
| ★ **ORM / JPA** | 객체↔테이블 자동 매핑 | `Subject` 엔티티 |
| ★ **관계형 DB** | 표와 관계로 저장 | PostgreSQL |
| ★ **OAuth 2.0** | 남의 서비스로 신원 확인 | 카카오 로그인 (Authorization Code) |

| ★ **HS256** | 대칭키 HMAC 서명 (**검증키 = 서명키**) | LiveKit 토큰·자체 토큰 |
| **refresh rotation** | 갱신 시 refresh도 새로 발급 | 옛 토큰 재등장 = 탈취 신호 |

## 4. 실시간 음성 ★ 가장 많이 물어봅니다

| 키워드 | 정의 | 왜 우리가 |
|---|---|---|
| ★ **WebRTC** | 브라우저 실시간 미디어 통신 | HTTP는 요청-응답이라 부적합 |
| ★ **UDP vs TCP** | UDP는 재전송 없음 | 음성은 **지연이 손실보다 치명적** |
| **head-of-line blocking** | 앞 패킷 재전송이 뒤를 막음 | TCP를 안 쓰는 이유 |
| **SRTP** | 암호화된 실시간 전송 프로토콜 | 미디어 채널 |
| ★ **ICE / STUN / TURN** | NAT 뒤 주소 찾기 / 알아내기 / 중계 | `use_external_ip: true` |
| ★ **SFU** | 디코드 없이 선택적 전달 | Mesh는 N² 폭발, MCU는 CPU 과다 |
| **Mesh / MCU** | P2P 전연결 / 서버 합성 | 비교 대상 (SFU를 고른 근거) |
| ★ **시그널링 vs 미디어** | 연결 협상 / 실제 소리 | **미디어는 nginx 프록시 불가** |
| ★ **STT** | 말 → 글자 | Deepgram |
| **interim / final transcript** | 임시 캡션 / 확정 문장 | 화면 캡션 vs 파이프라인 투입 |
| **VAD** | 발화 구간 감지 | **안 씀** — Deepgram이 경계를 줌 |
| **TTS** | 글자 → 말 | **일부러 미도입** (답변은 텍스트만) |

## 5. LLM 연동 ★

| 키워드 | 정의 | 우리 것 |
|---|---|---|
| ★ **LLM** | 대규모 언어 모델 | Gemini (게이트웨이 경유) |
| ★ **프롬프트** | 모델에게 주는 지시문 | `prompts/*.md`, 재시작 없이 반영 |
| ★ **구조화 출력 / constrained decoding** | 스키마 밖 토큰이 **선택 불가** | `responseSchema` |
| ★ **프롬프트 인젝션** | 사용자 입력이 지시처럼 작동 | `escape_slot_value`로 태그 이스케이프 |
| ★ **환각(hallucination)** | 그럴듯한 거짓 생성 | 없는 칸 지어냄 → **서버가 거부** |
| **토큰** | 모델의 처리·과금 단위 | 발화당 2회 호출 |
| **maxOutputTokens** | 출력 상한 | 512. 넘으면 잘림 |
| **propertyOrdering** | 필드 생성 순서 고정 | `reasoning`을 맨 뒤로 (잘려도 되는 것) |
| **자카드 유사도** | \|A∩B\| / \|A∪B\| | 바이그램으로 중복 과제 검색 |

## 6. 동시성 · 자원

| 키워드 | 정의 | 우리 것 |
|---|---|---|
| ★ **동기 vs 비동기** | 기다림 / 안 기다림 | `async/await`, I/O 대기가 대부분 |
| **이벤트 루프** | 단일 스레드로 비동기 처리 | asyncio |
| ★ **락(Lock)** | 동시 접근 제어 | 방마다 하나. **생성 중 발화는 버림** |
| **fork / COW** | 프로세스 복제 / 쓸 때만 실제 복사 | job=프로세스, 가중치를 공유 |
| ★ **cgroup** | 컨테이너 자원 격리·집계 단위 | `docker stats`가 이 값 |
| **백프레셔** | 못 받으면 거절해 상류를 늦춤 | 방 수 상한 → `reject(terminate=False)` |
| ★ **재시도 / 백오프** | 실패 후 기다렸다 다시 | 429만 1초 후 1회 |
| **429 / Retry-After** | 요청 과다 / 서버가 알려준 대기 | 상한 3초 초과면 재시도 포기 |
| **타임아웃** | 응답 대기 상한 | 단계 25초 / 전체 45초 |

## 예상 질문 & 짧은 답

| 질문 | 답의 뼈대 |
|---|---|
| **★ 왜 하필 만다라트?** | ① 세분화를 **강제**(빈 칸 64개가 먼저 있음. SMART는 한 문장이면 끝) ② 진행률에 **분모**가 생김(완료/64) → 마을 성장의 근거 ③ **칸이 유한해서 AI 출력을 서버가 판정 가능**(`DOMAIN_SLOTS=8`이 AI 권한의 경계). **오타니는 근거가 아니라 예시** |
| **★ 세 기능을 그냥 다 넣은 건 아닌가?** | 서로를 필요로 함 — 만다라트는 AI 없이 81칸 진입장벽, AI는 만다라트 없이 검증할 구조 없음, 게임화는 만다라트 없이 분모 없음 |
| **왜 WebRTC?** | HTTP는 요청-응답. 음성은 지속 스트림이고 지연이 손실보다 치명적 → UDP 기반 |
| **왜 SFU?** | Mesh는 인원당 업링크 N−1로 폭발, MCU는 디코드-합성-인코드로 CPU 과다. SFU는 라우팅만 |
| **왜 LiveKit Cloud 안 씀?** | 자체 EC2 호스팅. 비용·데이터 통제. 대신 TLS·포트·확장을 직접 해야 함 |
| **AI 헛소리는 어떻게 막나?** | ① 구조화 출력으로 형식 강제 ② **확인 가능한 값은 서버가 판정**(새 칸 여부, 제목) ③ 없는 칸이면 되묻기로 전환 |
| **왜 LLM을 2번 부르나?** | 3단계 중복검사에 후보 목록이 필요하고, 검색하려면 도메인을 알아야 함. 데이터 의존성 |
| **비용은?** | 발화당 2회. 목표와 무관한 말은 1단계에서 끊어 1회. 3단계는 싼 모델(flash-lite) |
| **왜 TTS 안 넣었나?** | 결정. 응답이 텍스트라 에이전트가 오디오를 발행하지 않아 구조가 단순해짐 |
| **JWT vs 세션?** | JWT는 서버가 상태를 안 들고 있어 확장이 쉬움. 대신 즉시 무효화가 어려워 refresh 회전으로 보완 |
| **Redis 왜?** | 리포트 생성에 LLM이 끼어 느림 → 결과 캐시 |
| **테스트 어떻게?** | 267개. 특이한 건 **import 차단으로 계층 분리를 검증**하는 것 |

## ⚠️ 답변 조심 — 근거가 약한 것

**단정하면 반박당하는** 항목입니다. 측정 조건은 [기술스택.md](기술스택.md)에 적어 뒀습니다.

| 질문 | 하면 안 되는 답 | 정확한 답 |
|---|---|---|
| **동시 사용자 몇 명?** | "수백 명 가능합니다" | **"측정하지 않았습니다."** 메모리는 병목이 아니고(COW), 가장 낮은 천장은 **LLM 게이트웨이 rate limit**으로 추정. 그래서 방 수 상한(`BOT_MAX_CONCURRENT_ROOMS`)을 걸 수 있게 해두고, 부하 테스트가 남은 일 |
| **SFU 부하는?** | "CPU 0.08%라 여유롭습니다" | **idle 값**입니다. 오디오가 흐르지 않는 상태라 부하 시 거동은 모릅니다. 가벼울 것으로 **추론**하는 이유는 비디오 없음·TTS 없음·방당 1명 |
| **메모리 얼마 필요?** | "757MB면 됩니다" | idle 기준 **하한** 757MB. job당 증가분은 미측정. **2GB 이상** 권장 |
| **응답 시간?** | "2.5초입니다" | **표본 3회, 단일 사용자** 기준 2.25~2.83초. 동시 요청 시 지연은 미측정 |
| **JWT 안전한가?** | "암호화돼 있어 안전합니다" | **암호화가 아니라 서명**입니다. payload는 Base64라 누구나 읽습니다. 위조만 막습니다 |
| **배포 다 됐나?** | "배포 완료" | 앱 서버는 배포 중. **AI EC2는 산출물만 준비**(Dockerfile·compose·livekit.yaml)되고 실제 배포·TLS는 남음 |

> **"측정하지 않았습니다"는 좋은 답입니다.** 추측을 숫자처럼 말하는 것보다 훨씬 신뢰를
> 얻고, 무엇을 재야 하는지 아는 사람으로 보입니다.

| **1월 셋째 주** | Strava Quitter's Day — 8.2억 건 분석, 최다 포기 시점 | ★★☆ 2차 출처 |
| **8~9%** | 새해 목표 성공률 | ★☆☆ 재인용 기사 |

> **한 줄 서사**: 습관은 **66일** 걸리는데 사람들은 **3주**에 포기하고, 앱은 **30일**도 못 버팁니다.
> 의욕은 있습니다(**77.2%**). 없는 건 그 사이를 버티게 할 구조이고, 게임화는 그 구조로 이미 검증됐습니다(**4.5배**).

⚠️ **하면 안 되는 말**: "저희도 Duolingo처럼 4.5배 늘릴 수 있습니다" → 게임화의 효과가 검증됐다는 것과 우리 서비스가 그렇게 된다는 건 다른 주장입니다. **우리 리텐션은 사용자가 없어 측정 자체가 불가**합니다.

## 실측값 한눈에 (조건 포함)

발표에서 숫자를 말할 때 **조건을 같이** 말하세요.

| 값 | 조건 |
|---|---|
| worker 컨테이너 757 MB | idle, 활성 job 0개 |
| livekit 컨테이너 32 MB / CPU 0.08% | idle, 방 0개, 오디오 미흐름 |
| 발화당 2.25~2.83초 | 단일 사용자, 표본 3회 |
| classify 1.34초 / decide 1.13초 (평균) | 같은 조건 |
| 프로세스별 RSS 합 6,017 MB vs cgroup 757 MB | COW 공유 확인 (8배 중복 계산) |
| 테스트 267개 | `pytest tests -q` (23개 파일, 전부 통과) |
